## Role Overview (summary — do not open files unless details are requested)

**A. Technical:** Software Architect, Lead Developer, Front-End Developer, Back-End Developer
**B. Management:** Project Manager, Scrum Master
**C. Design:** UX Designer, UI Designer, UX Researcher
**D. Testing:** QA Manual, QA Automation, Security Tester
**E. Infrastructure:** DevOps, SysAdmin, Release Manager
**F. Strategy:** Product Manager, Product Owner

## Usage Rules

1. If the user names one role -> open that role's category file, and only that role's section.
2. If the user names a specific task (e.g., "canary deployment") -> answer directly from the relevant file without reading other categories.
3. If the user asks for "all roles" -> summarize from the overview table above; do not open reference files unless the user asks for details on a specific role.
4. Small teams (5–7 people): roles can be combined (PM + Scrum Master, UX + UI, DevOps + SysAdmin, Front-End + Back-End as full-stack).
5. For desktop-native projects, use the sister skill `it-project-codename-royalchampion` instead.
